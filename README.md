# Oral virome in periodontal health and periodontitis

A small, reproducible virome sequencing pipeline built as a portfolio piece.
It covers QC and preprocessing of metagenomic reads, alignment to a viral
reference database, metadata curation in REDCap and NCBI submission formats,
and basic statistics on the resulting count table.

It runs on a laptop. One command runs everything.

## Question

In subgingival gingival crevicular fluid, does the viral fraction of the
metagenome differ in diversity or composition between periodontally healthy
subjects and periodontitis patients?

This is a reanalysis of public data. It is a demonstration of method, not a
clinical finding, and the original study was not designed to answer a question
about viruses.

## Data

**BioProject:** [PRJNA1183294](https://www.ncbi.nlm.nih.gov/bioproject/PRJNA1183294)

**Paper:** Arredondo A, Àlvarez G, Isabal S, Teughels W, Laleman I, Contreras MJ,
Isbej L, Huapaya E, Mendoza G, Mor C, Nart J, Blanc V, León R. Geographic
influence on subgingival microbiota in health and periodontitis: a
multinational shotgun metagenomic study. *Journal of Periodontal Research*.
2025 Sep;60(9):910-922. doi:[10.1111/jre.13406](https://doi.org/10.1111/jre.13406).
PMID 40202358.

The same 80 samples were reused for a resistome analysis: Arredondo A et al.
*Journal of Oral Microbiology*. 2026;18(1):2610588.
doi:[10.1080/20002297.2025.2610588](https://doi.org/10.1080/20002297.2025.2610588).
PMID 41522492.

The BioProject record carries no PubMed link. The paper was matched to the
accession by study design: the abstract describes 80 subgingival samples from
healthy and periodontitis subjects across Belgium, Chile, Peru and Spain,
which is exactly the sample table returned by NCBI.

### Why this dataset

Three reasons.

1. The health versus disease grouping is public and machine-readable. Every
   one of the 80 BioSample records carries a `Diagnosis` attribute with the
   value `Periodontally healthy` or `Periodontitis`. Most candidate studies
   bury the grouping in a paper supplement or leave it inferable only from a
   sample-name prefix.
2. The design is balanced. 40 healthy and 40 periodontitis, 10 of each in each
   of four countries.
3. The specimens are subgingival gingival crevicular fluid collected on paper
   points, which is directly relevant to periodontal research, and the files
   are around 1 GB each, which is tractable on a laptop.

### Samples used

16 of the 80, selected by a rule fixed before any data was downloaded:
stratify by country and diagnosis, sort sample names lexicographically, take
the first two from each of the eight strata. This gives 8 healthy and 8
periodontitis, 2 of each per country.

The selection is in `config/samples.tsv` and the full 80-sample table is in
`config/bioproject_all_samples.tsv`. Both are generated by
`tools/make_manifest.py` directly from NCBI, so the manifest is not
hand-typed and the selection can be audited.

## How to run

```bash
# 1. Build the pinned environment
conda env create -f envs/pipeline.yaml
conda activate oral-virome

# 2. Run everything
snakemake --cores 4
```

That downloads the data, runs QC, aligns to the viral reference, builds the
count table, generates the metadata deliverables, validates them, runs the
statistics and writes `report/report.pdf`.

To check the workflow without downloading 15 GB:

```bash
snakemake --cores 4 -n          # dry run, builds the full DAG
pytest tests/ -v                # validator unit tests
snakemake --cores 2 results/metadata/validation_report.txt   # metadata only
```

The manifest can be regenerated from NCBI with
`python tools/make_manifest.py`.

## Pipeline

| Step | Tool | Why |
|---|---|---|
| Download | sra-tools `prefetch` and `fasterq-dump` | The official client. Resumes, and verifies the transfer. |
| Subsample | `seqtk sample`, fixed seed | Equalises depth across samples and keeps the run under an hour. |
| QC before | FastQC | Baseline read quality and adapter content. |
| Trim and filter | fastp | One pass for adapter detection, quality trimming and length filtering. Emits a JSON the retention table reads. |
| QC after | FastQC | Confirms trimming worked rather than assuming it. |
| Summary | MultiQC | One report across all 16 samples and both QC passes. |
| Align | bowtie2 against RefSeq viral | See below. |
| Filter | samtools, MAPQ and proper pair | Removes low-confidence and orphan alignments. |
| Count | `samtools coverage` | Gives read count and breadth of coverage per reference in one pass. |
| Statistics | R, vegan | Alpha diversity, Bray-Curtis, PCoA, PERMANOVA. |

### Why bowtie2 and not Kraken2

Both were viable. bowtie2 against NCBI RefSeq viral genomes was chosen
because alignment is auditable in a way k-mer classification is not. Every
count traces to a specific read aligned at a specific position on a named
reference, so a suspicious result can be inspected in the BAM. It also yields
breadth of coverage for free, which is the single most useful signal for
telling a real low-abundance virus from reads piled on one repetitive locus.

Kraken2 with a small viral database would be faster. Its weakness matters
here: k-mer classification against a viral-only database has a high false
positive rate on bulk metagenomes, because bacterial and host k-mers that
happen to match prophage or low-complexity viral regions get assigned to
viruses with no coverage information to contradict them.

The reference is RefSeq viral release 237, a single 178 MB file. The release
number and checksum are recorded in `resources/refseq_viral.source.txt` at
download time.

### Host read removal: not performed, deliberately

Human reads were **not** depleted before alignment. This is a laptop
concession and it is a real limitation.

Doing it properly means downloading the human reference (about 3 GB), building
a bowtie2 index (several hours and roughly 4 GB on disk) and aligning every
read against it before the viral step. That does not fit the constraint that
this runs on a laptop in about an hour.

What it changes: human sequence can align spuriously to viral references,
especially to endogenous retrovirus-like regions and low-complexity stretches.
The effect is to inflate apparent viral counts. Two filters reduce it. Only
properly paired alignments at MAPQ 30 or above are counted, which discards
reads that map ambiguously or in multiple places. A virus is only called
present when at least 10 reads spread over at least 1 percent of its genome,
which removes the characteristic signature of spurious mapping, a tall narrow
pile on one locus.

Those filters reduce the problem. They do not eliminate it. Any absolute viral
abundance here should be read as an upper bound. Host contamination may also
differ between groups, since inflamed periodontal tissue sheds more host cells,
so the between-group comparison is not protected from this bias either.

The source paper states that its authors depleted human DNA before their own
analysis. Whether the reads deposited in SRA are pre- or post-depletion could
not be determined from the metadata, so the conservative assumption is that
host reads are present.

## Metadata

The metadata deliverables are in `results/metadata/`.

| File | What it is |
|---|---|
| `redcap_data_dictionary.csv` | REDCap data dictionary, 18-column import format, three forms |
| `redcap_records.csv` | Matching records CSV, import-ready |
| `biosample_MIMS_human_oral.tsv` | NCBI BioSample attributes, package MIMS.me.human-oral.6.0 |
| `sra_metadata.tsv` | NCBI SRA library and run sheet |
| `validation_report.txt` | Output of the validator |

Every format rule and its documentation source is recorded in
[`docs/metadata_standards.md`](docs/metadata_standards.md). That file also
records what could not be verified.

### The validator

`workflow/scripts/validate_metadata.py` checks the three things that actually
cause rejected submissions and unusable study databases:

1. **Missing required fields.** REDCap fields marked required, and the seven
   mandatory MIMS attributes, must carry a value. For NCBI, one of the INSDC
   missing terms counts as a value; an empty cell does not.
2. **Sample IDs that disagree across files.** The manifest, the REDCap
   records, the BioSample sheet and the SRA sheet must describe the same set
   of samples.
3. **Values that are invalid for their declared type.** Radio codes that are
   not in the dictionary, labels pasted where codes belong, dates in the wrong
   format, non-numeric values in integer fields, values outside declared
   ranges, and controlled vocabulary violations in the SRA sheet.

It exits non-zero on any error, so the workflow fails rather than producing a
report nobody reads.

Two curation decisions worth noting, both caught by checking rather than
assuming:

- `ENVO:00009003` "human-associated habitat" is widely used in real
  submissions but is **obsolete**, with no replacement term.
- `UBERON:0006932` is **vestibular epithelium**, not gingival crevicular
  fluid. No ontology term for gingival crevicular fluid exists in ENVO or
  UBERON at all.

See `docs/metadata_standards.md` for what was used instead and why.

### Tests

`tests/test_validate_metadata.py` contains 40 tests. One asserts that valid
metadata passes. The other 39 break exactly one thing each and assert the
validator catches that specific problem, including the obvious real-world
mistakes: a dropped question mark in the `Identifier?` column header, a choice
label written where the numeric code belongs, signed decimal coordinates
instead of NCBI's compass-direction format, and a sample present in one file
but not another.

```bash
pytest tests/ -v
```

## Results

**Headline: the result is null, and the run is dominated by a host artefact.**

Periodontitis and periodontal health did not differ in viral alpha diversity or
in Bray-Curtis composition. PERMANOVA on diagnosis gives R2 = 0.017 and
p = 0.98, which is about as close to no signal as this test produces.

That null should not be read as evidence that the oral virome is unrelated to
periodontitis. It is mostly a statement about the data and the method. Only
around 0.005 percent of post-QC reads aligned to RefSeq viral, roughly 20 to 75
read pairs per sample, and 90 percent of those reads sit on just two references.
The larger of the two is a human endogenous retrovirus, which is host genomic
sequence rather than a virus, and the second carries NCBI's own UNVERIFIED_ORG
flag. Alpha diversity of 1 to 2 "viruses" per sample is therefore largely
counting artefacts.

This is the predicted consequence of skipping host depletion on a bulk
metagenome, stated as a limitation before the run and then confirmed by it. The
thresholds were fixed in advance and were not adjusted after seeing this.

See [`report/report.pdf`](report/report.pdf) for the one-page summary.

## Limitations

1. **Cross-sectional.** Any difference between groups is an association. This
   design cannot show that periodontitis changes the virome or that the virome
   contributes to periodontitis.

2. **Subsampling discards most of the data.** Each sample is cut to a fixed
   number of read pairs with a fixed seed so the pipeline finishes on a laptop
   and so depth is equal across samples. This lowers sensitivity to rare
   viruses. Richness in particular is depth-dependent, and the values here
   are not comparable to a full-depth analysis.

3. **This is a bulk metagenome, not a virome.** The library was not enriched
   for virus-like particles. Viral reads are a small fraction of the total and
   are dominated by bacteriophage. Counts are sparse, and a study designed to
   sequence the virome would produce a much richer table.

4. **No host depletion.** Discussed above. Absolute viral abundances should be
   treated as upper bounds.

5. **Small n, and country is confounded with everything.** 8 samples per
   group. The source paper found that country of origin explained more
   compositional variance than diagnosis did. With 2 samples per group per
   country, this subset cannot cleanly separate the two. The PERMANOVA is run
   both with and without country for that reason.

6. **Reference-based detection only.** Viruses absent from RefSeq viral are
   invisible here. Much of the oral virome is uncharacterised phage, so this
   undercounts real diversity in a way that is hard to quantify.

7. **The presence filter is a judgement call.** 10 reads and 1 percent breadth
   were fixed before results were seen and were not adjusted afterwards, but
   different thresholds would give different richness values. The raw counts
   are published alongside the filtered table so the effect can be checked.

## Reproducibility

- All package versions are pinned in `envs/pipeline.yaml`, with the fully
  resolved dependency set in `envs/pipeline.lock.yaml` and
  `envs/pipeline.explicit.txt`.
- Subsampling uses a fixed seed, declared in `config/config.yaml`.
- R uses a fixed seed; PERMANOVA uses 9999 permutations.
- The reference URL, RefSeq release number, SHA-256 and retrieval timestamp
  are written to `resources/refseq_viral.source.txt` during the run.
- `results/stats/r_session_info.txt` records the R session.
- CI runs the unit tests and a Snakemake dry run on every push, and builds and
  validates the metadata deliverables for real.

## Integrity notes

Every number in the report and in this README is read from a file the pipeline
wrote. No result is typed by hand.

Parameters were fixed before results were inspected and were not adjusted
afterwards. Where the result is null or weak, it is reported as null or weak.
